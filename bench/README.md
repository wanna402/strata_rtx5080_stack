# bench/ — 这台机器的实测速度与方法

`bench_speed.py` 是我加的**可重复测速脚本**（上游 `BENCH.bat` / `strata bench run` 那套是给社区横向对比用的，
会按它自己的参数重启模型；这里要量的是**你日常这套参数**，所以直接打 8083）。

## 怎么量

数字不靠客户端掐表，而是解析引擎自己打在 `log\8083_main_YYYYMMDD.log` 里的统计行：

```
strata serve: prompt 72126 tokens = 32768 reused + 39360 read in 14427 ms (2728.1 tok/s),
              499 generated in 10687 ms (46.7 tok/s), drafts accepted 203 of 268
```

- **输入速度（prefill）** = `read in … ms (X tok/s)`，即引擎真读进 KV 的 token 吞吐（不含被复用的部分）。
- **输出速度（decode）** = `generated in … ms (Y tok/s)`，含 MTP 投机解码的实际收益。
- 每次请求的 prompt 都带随机 nonce，保证不会被 prompt cache 命中（否则会虚高）。

用法（栈已在 8083 跑起来时）：

```bat
H:\Strata-main\.venv\Scripts\python.exe H:\Strata-custom\bench\bench_speed.py
:: 可选: --reps 3 --max-tokens 512 --prompts 4096,16384,32768 --tag 我的标签
```

结果写到 `bench/results/<时间>-<tag>.json`。

## 2026-10-24 实测（DDR4-2400，引擎 0.1.47 vs 0.1.48，同一台机同一套参数）

同参数对照：输入约 7.5K / 约 60.8K token，每次输出 512 token，各 2 次取平均。**只有引擎版本不同**。

| 项目 | 0.1.47 | 0.1.48 | 变化 |
| :--- | ---: | ---: | ---: |
| 输入 7.5K (tok/s) | 2503.8 | 2581.7 | **+3.1%** |
| 输入 60.8K (tok/s) | 2484.6 | 2711.2 | **+9.1%** |
| 输出 512 @7.5K 输入 (tok/s) | 57.2 | 57.3 | ±0 |
| 输出 512 @60.8K 输入 (tok/s) | 48.6 | 55.5 | **+14.2%** |

结论：升级后**没有变慢**。长输入（>8K）的读入更快，长上下文下的输出也更快（0.1.48 的专家缓存多拿了约 0.25 GiB：
3683 槽 → 3813 槽）。

## 0.1.48 + 源码层 0.2.4.2 · 方案 A · 四档输入（输出 256 token，各 3 次）

| 实际输入 token | 输入速度 | 输出速度 |
| ---: | ---: | ---: |
| 1,787 ~ 1,912 | 709.6 | 57.7 |
| 7,051 ~ 7,534 | 2629.5 | 59.2 |
| 29,696 ~ 30,075 | 2791.5 | 58.3 |
| 60,504 ~ 60,977 | 3024.5 | 62.9 |

- 输入越快越长：2K 以内的 prompt 被固定开销（建 KV 窗口、读窗口）拖到 ~700 tok/s；8K 以上稳定 2600~3000 tok/s。
- 60K 的 prompt 大约 20~22 秒读完，这是 128K 上下文 + 16G 显存的正常水平。

## 方案 B（纯文本）在 2400 下

| 输入 | 输入速度 | 输出速度 |
| ---: | ---: | ---: |
| 7.4K ~ 7.7K | 2511.9 | 55.2 |
| 60.9K ~ 61.5K | 2716.2 | 54.6 |

方案 B 这次自动拿到 3858 槽 / 7.37 GiB 专家缓存，只比方案 A 的 3813 槽多 45 槽——所以**没测出过去文档里
"65-75+ tok/s" 的差距**。那个数字来自真实对话日志（专家画像 `profile-coding.bin` 已经被真实流量喂热，
命中率更高），我这套随机文本 prompt 的命中率是 79~82%，会比真实使用略低。

## 升级前的历史对照（从 `log\8083_main_20261020.log` 的 303 次真实请求里统计）

那是引擎 0.1.45 时期（推断内存还在 3200）：

| 指标 | 历史均值 | 今天（2400，0.1.48） |
| :--- | ---: | ---: |

## 口径提醒

- 同一台机、同一频率下，**输入速度基本没受内存降频影响**（prefill 主要吃 GPU 和显存带宽，专家缓存在显存里）。
- **输出速度**受内存影响也有限：引擎日志显示 decode 期间专家缓存命中 79~82%，只有 5~8% 的专家走
  RAM/PCIe，KV 命中 99.4% 在显存里。所以 3200→2400（理论带宽 -25%）落到实际出字大约是个位数百分比。
- 差异大的场景是：上下文很长、专家缓存命中率下降、或者同时跑别的吃内存的程序。
