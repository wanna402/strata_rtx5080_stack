实测速度 (2026-10-24, 内存 DDR4-2400, 方法见 bench/README.md):
  同机同参数只换引擎 (输入约 7.5K / 60.8K token, 输出 512 token, 各 2 次):
    输入 7.5K : 0.1.47 2503.8 -> 0.1.48 2581.7 tok/s  (+3.1%)
    输入 60.8K: 0.1.47 2484.6 -> 0.1.48 2711.2 tok/s  (+9.1%)
    输出 512 @7.5K  输入: 57.2 -> 57.3 tok/s  (±0)
    输出 512 @60.8K 输入: 48.6 -> 55.5 tok/s  (+14.2%)
  0.1.48 方案A 四档输入 (输出 256 token, 各 3 次):
    输入 1.8K -> 709.6 tok/s | 7.3K -> 2629.5 | 29.9K -> 2791.5 | 60.6K -> 3024.5
    输出分别 57.7 / 59.2 / 58.3 / 62.9 tok/s
  结论: 升级没有变慢. 长时间上下文 (60K) 的输出比 0.1.47 快约 14%.
  内存降频影响有限: decode 期间专家缓存命中 79~82%, KV 命中 99.4%, 只有 5~8% 的专家走 RAM/PCIe,
  所以 3200->2400 (理论带宽 -25%) 落到实际出字只有个位数百分比.
  复测: H:\Strata-main\.venv\Scripts\python.exe H:\Strata-custom\bench\bench_speed.py

已知事项:
  - 内存: 2x32G 光威 TAC4U3200E18321C, 目前跑 JEDEC 2400 (1.2V, XMP 未生效), 3200 进不了系统.
    两条序列号不同批 (D4322290 / D4322352), 双面 32G 条 + 12 代 IMC 本来就吃紧, 混批更难稳.
    2026-10-24 出现过两次非正常关机 (20:12 关机事件 6008 / 19:36 有一个 minidump).
  - 16G 显存在 131072 上下文下只剩约 0.6G 可用, 引擎会告警. 这是既有状态(0.1.45 就有),
    不是升级引入; 想更稳就把 configs 里 --vram-reserve-mib 从 1024 提到 1536
    (专家缓存会小一点, 命中率略降).
  - 引擎是官方 Strata 0.1.48, 源码层是官方 Strata 0.2.4.2, 两边都未做任何改动; 定制层只在之上加启动器/网关/配置.
  - 0.1.48 在 131072 上下文下给自己多拿了约 0.27 GiB 专家缓存 (3940 槽 / 7.52 GiB),
    只剩约 395 MiB 显存; 引擎日志建议 --vram-reserve-mib 1856. 当前配置仍为 1024 (速度优先).
